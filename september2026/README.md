# september2026 — LB, CB, ρ, LB із двоточкової матриці Мюллера (Крок B)

Цей проєкт реалізує **Крок B**: бере вже готові комплексні двоточкові
елементи матриці Мюллера `f_ik` (Крок A — старі, незмінені скрипти з
`august2026`) і рахує з них 5 похідних величин — `LB₀,₉₀`, `LB₄₅,₁₃₅`,
`CB`, `ρ`, `LB` — за формулами з `techn-zavd\Теорія поляризаційно-
кореляційна томографія.docx`. Формули верифіковані буквально (див.
`verify\`) проти нативної комплексної арифметики MATLAB (`log`, `atan`,
`sqrt`) з похибкою ~1e-14.

## Структура папок

```
september2026\
├── techn-zavd\           Оригінальний вордівський документ з формулами (джерело істини)
├── core\                 Крок A — СКОПІЙОВАНО ДОСЛІВНО з august2026, не чіпати
├── config\                 cfg_TwoPoint.m — конфіг Кроку A (для довідки)
├── LB_CB_rho\            Крок B — уся нова математика й оркестрація (наш код)
├── viz\                  Візуалізація — копії з august2026 + власні правки стилю
├── io\                   tp_save_figure.m — збереження рисунків (спільне для всього)
├── verify\               Числова перевірка формул і даних
└── run_LB_CB_rho_demo.m  Наскрізний приклад: реальні дані -> Крок B -> рисунки
```

### `core\` — Крок A (не чіпати)

Байт-в-байт копії з `august2026`, обчислюють `f_ik` з сирих `Ex,Ey`:

| Файл | Призначення |
|---|---|
| `tp_fik_pair.m` | Головна формула: 16 комплексних `f_ik` з пари точок |
| `tp_load_mat.m` | Завантажує `ex_*.mat`/`ey_*.mat` (6 станів: 0,45,90,135,liv,prav) |
| `tp_slice.m` | Вирізає підобласть зображення для пари точок |
| `tp_assert.m` | Єдиний стиль перевірки передумов |
| `tp_moments.m`, `tp_acf_psd.m`, `tp_acf_hwhm.m`, `tp_multifractal.m`, `tp_piecewise_loglog_fit.m`, `tp_contour_levels.m`, `tp_format_level.m`, `tp_smooth2.m`, `tp_validate.m` | Допоміжні розрахунки для візуалізації (АКФ/PSD, статистичні моменти, мультифрактал, контури, QC) |

### `LB_CB_rho\` — Крок B (наш код)

Кожен зелений блок формули — **окремий файл**, номер блоку в імені:

| Файл | Блок | Формула |
|---|---|---|
| `tp_B0_cross_log_ratio.m` | B.0 | Спільний примітив: `ln(z1/z2)` -> Re,Im,модуль,аргумент |
| `tp_B1_LB_0_90.m` | B.1 | `LB₀,₉₀ = ln(f34/f43)` |
| `tp_B2_LB_45_135.m` | B.2 | `LB₄₅,₁₃₅ = ln(f24/f42)` |
| `tp_B3_CB.m` | B.3 | `CB = ln(f23/f32)` |
| `tp_B4_rho.m` | B.4 | `ρ = ½·atan(LB₄₅,₁₃₅/LB₀,₉₀)` |
| `tp_B5_LB_total.m` | B.5 | `LB = √(LB₀,₉₀² + LB₄₅,₁₃₅²)` |
| `tp_LB_CB_rho.m` | — | Тонкий оркестратор: викликає B.1-B.5 у правильному порядку |
| `tp_LB_CB_rho_from_result.m` | — | Адаптер: бере `result.mat` Кроку A (`R.data.(dir).f_mn.cplx`), повертає `R2` у тій самій формі, готовій для візуалізації |
| `tp_save_LB_CB_rho_result.m` | — | Зберігає числові карти (mod/arg/cplx) усіх 5 величин в один `result.mat` |
| `tp_visualize_LB_CB_rho.m` | — | Викликає всі 13 подань (`viz\`) для кожного з 5 елементів |
| `cfg_LB_CB_rho_viz.m` | — | **Єдиний конфіг** для наших рисунків: шляхи, шрифт/кегль, кольори, DPI (той самий принцип, що `paper_figures\cfg_figures.m` в `august2026`, але без мм-геометрії композитних рисунків) |

Кожен блок (B.0-B.5) можна викликати й тестувати окремо — жодних
прихованих залежностей між ними, крім явних вхідних аргументів
(`rho`/`LB` беруть готові `LB_0_90.cplx`/`LB_45_135.cplx`, а не рахують
щось наново).

### `viz\` — візуалізація (13 подань на елемент)

Копії з `august2026\viz\` + власні правки (стиль через `CFG.style`,
"картинка в картинці" для ACF, обрізана шкала PSD, лінійна вісь і
фіксовані масштаби для wavelet, 9-рівнева `level_bands` з модою
розподілу):

`viz_maps_hist`, `viz_block1_summary`, `viz_sections`, `viz_contour3d`,
`viz_block3_contours`, `viz_multifractal`, `viz_multifractal_dimensions`,
`viz_wavelet`, `viz_acf_psd`, `viz_acf_cuts`, `viz_skeleton`,
`viz_level_bands`, `viz_stats_table`, `viz_style.m` (спільний стиль).

### `verify\` — перевірка

| Файл | Що перевіряє |
|---|---|
| `verify_theory_formulas.m` | Формули docx (Re/Im/mod/arg) проти нативної арифметики MATLAB — сюди ж входить emпіричне підтвердження `atan4(a,b) ≡ atan2(a/2,b)` |
| `verify_block_B1..B5_*.m` | Кожен блок Кроку B ОКРЕМО, випадкові комплексні дані |
| `verify_tp_LB_CB_rho.m` | Повний Крок B наскрізно (усі 10 виходів) |
| `run_all_verify.m` | Запускає всі перевірки вище по черзі |
| `scan_september_data_health.m` | Сканує `C:\September 2026-Results\Зразки...` на "биті" (дійсні замість комплексних) канали -- визначає, які зразки придатні для тестів |
| `compare_f34_f43.m` | Пряме порівняння карт `f34` і `f43` на реальних даних (демонструє, що вони справді різні, кореляція ≈0) |

Запуск усього одразу:
```matlab
cd september2026\verify
run_all_verify
```

  скан-алгоритму (`tp_algo_*.m` з `august2026\core\algo\`, поки не

## Позначення на рисунках

Точно як у документі: `|LB₀,₉₀|`, `arg[LB₀,₉₀]` (квадратні дужки — для
LB₀,₉₀/LB₄₅,₁₃₅/CB), `|ρ|`, `arg(ρ)` (круглі дужки — для ρ/LB).
